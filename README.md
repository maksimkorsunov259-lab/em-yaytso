# ЕмЯйцо · 1.0.0

Рабочее приложение на основе утверждённого макета 07. Статическая PWA без сервера данных, регистрации и аналитики. Автор: Коршунов Максим Александрович.

## Возможности

- Несколько пациентов: имя, дата рождения, отдельный план, дневник, пауза, история рецептов и решений врача. Верхние кнопки «Изменить профиль» и «Пациенты».
- Реальные даты, календарь последних семи дней и ежедневный чек-лист.
- Семь ступеней, 17 рецептов, три отдельных показателя на полную порцию по таблице автора. Измеренные показатели без данных остаются «—».
- Выбор только разрешённых врачом рецептов, отдельный учёт каждого периода. Другой рецепт не наследует результат предыдущего. Малые порции не суммируются в полную.
- Наблюдение учитывает фактическое истечение назначенных интервалов и отметки семьи. При реакции сохраняется пауза; смена рецепта и ступени блокируются до внесения результата клинической оценки.
- Отчёт выбранного пациента, текстовый экспорт и печать/PDF. Копирование всех дневников в JSON; восстановление с добавлением отдельных профилей либо полной заменой после подтверждения.
- IndexedDB с атомарной записью и проверкой версии между вкладками. Ошибка сохранения останавливает редактирование и позволяет выгрузить несохранённые изменения.
- Авторский блок на каждом экране. Фотография и QR-код побайтно совпадают с ЕмМолоко.

## Медицинская основа

Сохранены содержание и ограничения макета. Семиступенчатая лестница Hicks 2026 аналитически стандартизирована, но клинически не валидирована. Приложение также не проходило клиническую валидацию. Выбор/замена рецептов и счётчики — проектные правила приложения, а не валидированный алгоритм Hicks.

Рецепты и источники перенесены из предоставленных автором материалов. Отмеченные редакционные расхождения с первоисточником не скрыты и требуют сверки. Количество аллергенов домашней партии не измеряется; безопасная доза по доле блюда не рассчитывается. Приложение сохраняет готовое назначение врача и наблюдения, не назначает лечение и не разрешает переход автоматически.

## Отдельная установка

Публиковать приложение в **отдельном репозитории `em-yaytso`**, в корне его GitHub Pages:

- предполагаемый адрес после публикации: `https://maksimkorsunov259-lab.github.io/em-yaytso/`;
- manifest id: `/em-yaytso/`, start_url и scope: `./`;
- service worker: `./sw.js`, только в области этого приложения;
- кэш: `em-yaytso:<путь>:<версия>`, база: `em-yaytso.diary.v1`.

Не публиковать файлы в корень другого приложения. Не копировать его manifest или service worker. При смене публичного пути необходимо согласованно изменить manifest id. Приложение не удаляет кэши других приложений на том же домене.

Android: открыть опубликованный HTTPS-сайт в Chrome → «Установить приложение». iPhone/iPad: Safari → «Поделиться» → «На экран Домой». Первый запуск требует сети. После подготовки кэша дневник, справка и рецепты работают без сети; внешние ссылки — с сетью. Это установка с сайта, без App Store и Google Play.

Исходная иконка `assets/icon-original.png` сохранена побайтно: SHA-256 `4d77e1e1d75b8900f4ad8dd6561b9fedac5f33c05c16f601b55c3bcb28b02239`. Для установщика Chrome `icon.svg` оборачивает **те же PNG-байты**, без перерисовки, обрезки или изменения цветов. Масштабирование делает браузер. Apple Touch Icon использует исходный PNG.

## Хранение и перенос

Данные находятся в браузере на устройстве. Синхронизации между устройствами/браузерами нет. Установка в отдельный контейнер, удаление приложения или очистка данных сайта могут повлиять на доступ к дневнику. Перед переносом, переустановкой и очисткой скачайте резервную копию. Файл JSON не зашифрован; защищайте его как медицинские сведения. Импорт других приложений и учебных макетов не поддерживается.

## Локальная разработка

Node.js 20+ — для тестов; Python 3 — для локального сервера. Сборка и npm-зависимости не нужны. Из каталога, содержащего папку `em-yaytso`:

```sh
python -m http.server 8028 --bind 127.0.0.1
node --test em-yaytso/tests/core.test.cjs
```

Браузерные проверки используют Python Playwright и Chromium. Установите их в рабочей среде, затем:

```sh
python em-yaytso/tests/browser_flows.py
python em-yaytso/tests/browser_edges.py
python em-yaytso/tests/storage_failure.py
```

Переменная `APP_URL` позволяет указать другой локальный URL, `CHROMIUM_PATH` — путь Chromium. Проверки используют только синтетические данные, результаты помещают во временный каталог. Проверка совместного размещения в `browser_edges.py` требует также соседние каталоги `em-moloko` и `dyshu-diary`; иначе проверяется только ЕмЯйцо.

После изменения статических ресурсов обновить версию кэша:

```sh
python em-yaytso/tools/build_sw.py
```

`app.js` — экраны и рецептурная логика утверждённого макета; `runtime.js` — профили, сохранение, копии, установка; `model.js` — схема и проверка данных; `storage.js` — атомарное хранилище; `recipes.js` — справочные данные.

## Публикация

1. Создать публичный репозиторий `maksimkorsunov259-lab/em-yaytso` и подключить его к рабочей среде Codex.
2. Разместить содержимое приложения в корне ветки `main`, включая `assets`, `manifest.webmanifest`, `sw.js` и `.nojekyll`.
3. GitHub → Settings → Pages → Deploy from a branch → `main` / `/ (root)`.
4. После успешной публикации проверить адрес, установку и повторное открытие именно ЕмЯйцо на реальных Android и iOS.

Репозиторий приложения: https://github.com/maksimkorsunov259-lab/em-yaytso. Для запуска публичного адреса включите GitHub Pages по инструкции выше и дождитесь завершения публикации.

- Chromium: ввод плана, выбор/замена рецепта, записи и реакция, клиническое решение, изоляция пациентов, перезагрузка, импорт/экспорт, офлайн, конфликт вкладок, отказ записи и восстановительная копия.

- Chrome DevTools: манифест без ошибок, проверка installability без ошибок в обычном профиле.
- Реальная установка на Android/iOS и опубликованный HTTPS-адрес ещё не проверены: для этого нужна публикация.
